# AlEntlaq POS

## قاعدة البيانات

يستخدم التطبيق ملف Microsoft Access بصيغة `.accdb` على جهاز Windows مركزي. تتصل محطات البيع بخدمة Next.js على الشبكة المحلية؛ لا تفتح محطات البيع ملف Access مباشرة ولا تضعه على مجلد SMB مشترك.

هذه البنية تستهدف نشرًا صغيرًا (3–5 محطات) مع اختبار تزامن فعلي قبل التشغيل. ملف Access محدود بالحجم والتزامن؛ إذا زاد عدد المحطات أو كثرت الكتابات المتزامنة، استخدم قاعدة خادمية مثل PostgreSQL أو SQL Server بدل Access.

## إعداد جهاز الخادم

المتطلبات:

- Windows 64-bit وNode.js 24 x64.
- مشغّل Microsoft Access ODBC / Access Database Engine 64-bit.
- نسخة المشروع واعتمادياته، مع السماح بتشغيل سكربت تثبيت `odbc`.
- إعداد جدار حماية Windows للسماح بالمنفذ المحدد من أجهزة الشبكة المحلية فقط. لا تعرض الخدمة مباشرة على الإنترنت؛ استخدم HTTPS عند عبور شبكة غير موثوقة.

أنشئ ملفًا جديدًا؛ يرفض السكربت استبدال ملف موجود:

```powershell
.\scripts\create-access-database.ps1 -Path 'C:\AlEntlaqPOS\Data\AlEntlaqPOS.accdb'
```

أنشئ ملف إعدادات للخادم (ولا تضعه في نسخة تطبيق محطات البيع):

```dotenv
ACCESS_DB_PATH=C:\AlEntlaqPOS\Data\AlEntlaqPOS.accdb
POS_API_TOKEN=ضع-قيمة-عشوائية-طويلة-هنا
POS_PORT=3000
```

يمكن حفظ الإعدادات في `.env.local` أو `.env` في مجلد المشروع. يجب أن يتطابق `POS_API_TOKEN` مع القيمة في إعداد كل محطة. لا تضف أسرار قاعدة البيانات إلى ملفات التوزيع.

ثبّت الاعتماديات وابنِ نسخة الخادم العادية (لا تستخدم `build:electron` على جهاز الخادم):

```powershell
pnpm install
pnpm build
```

## تشغيل الخادم ومحطات البيع

### حزمة خادم جاهزة (تشغيل يدوي، دون أدوات تطوير عند العميل)

على جهاز التطوير Windows x64 مع Node.js 24 x64 نفّذ `pnpm package:host`.
ينشئ بناء خادم مستقلًا في `.next-host` دون استبدال بناء المحطات، ويخرج
`release\AlEntlaqPOS-Server-<version>-win-x64.zip` مع Node.js وترخيصه واعتماديات التشغيل.
الإصدار الحالي هو `2.4.0`. تتضمن أسماء حزم الخادم والمحطة رقم الإصدار؛ حزمة المحطة الحالية
`dist-v23\AlEntlaqPOS Setup 2.4.0.exe` وحزمة الخادم `release\AlEntlaqPOS-Server-2.4.0-win-x64.zip`.
يتطلب الإنترنت لجلب ترخيص Node الرسمي إن لم يكن مثبتًا بجوار ملفه التنفيذي.
يرفض استبدال حزمة موجودة بالاسم نفسه؛ انقل الحزمة السابقة قبل إعادة التجهيز.
الحزمة لا تنسخ ملفات البيئة أو قاعدة البيانات، ولا تحتاج إلى `pnpm install` أو بناء على جهاز العميل.

فك الحزمة في مجلد إصدار مستقل، واتبع [تعليمات الخادم العربية](scripts/host/SERVER-GUIDE.md)
المرفقة داخلها. إعدادات العميل محفوظة خارج مجلد الإصدار في `ServerConfig\server.env`، والتشغيل
بالنقر على `start.cmd` والإيقاف بـ Ctrl+C من نافذته. لا تضبط هذه الحزمة تشغيلًا تلقائيًا.
يظل مشغّل Microsoft Access ‏64-bit مطلوبًا. أوقف الخدمة القديمة وعطّل مهمتها التلقائية إن وجدت،
وخذ نسخة احتياطية قبل أول تشغيل أو تحديث. لا تستبدل قاعدة العميل أو رمز الاتصال.
لا تنقل المجلد بعد أول تشغيل؛ أعد استخراج ZIP في المكان الجديد لاستعادة روابط الاعتماديات بشكل صحيح.

### التشغيل من نسخة المشروع (الطريقة السابقة)

ابدأ خدمة الخادم بعد الترحيل:

```powershell
pnpm start:host
```

عند أول تشغيل، تنشئ الخدمة الجداول والفهارس والعلاقات اللازمة. لا تغيّر مسار ملف Access أثناء تشغيل الخدمة، وأنشئ النسخ الاحتياطية بعد إيقافها وإغلاق جميع المحطات.

في قاعدة جديدة، تُنشأ حسابات المستخدمين الافتراضية الناقصة فقط؛ غيّر كلمات مرورها قبل الاستخدام الفعلي.

على كل محطة، افتح ملف `server.json` الذي ينشئه التطبيق أول مرة ضمن مجلد بيانات المستخدم في Windows (عادةً `%APPDATA%\AlEntlaqPOS\server.json`) واضبطه على عنوان الخادم والرمز المشترك:

```json
{
  "serverUrl": "http://192.168.1.10:3000",
  "apiToken": "نفس-قيمة-POS_API_TOKEN-على-الخادم"
}
```

يمكن بدلًا من ذلك ضبط متغيري البيئة `POS_SERVER_URL` و`POS_API_TOKEN` للمستخدم. لا تضع ملف `.env` الخاص بالخادم في أجهزة العملاء.

أسماء البنوك والخزائن فريدة ولا يمكن تكرارها. عند ظهور رسالة بأن الاسم مسجل بالفعل، استخدم الحساب الموجود أو اختر اسمًا مختلفًا؛ إعادة المحاولة بالاسم نفسه لن تنشئ حسابًا آخر. يتطلب تحديث رسائل الأخطاء تحديث الخادم وتطبيق المحطة معًا.

زر القلم في بطاقة البنك يفتح تعديل الحساب الموجود، بما في ذلك الرصيد المعروض، دون إنشاء حساب جديد أو تغيير ارتباط سنداته. زر الإضافة ينشئ حسابًا جديدًا مستقلًا.

يمكن فتح «كشف حساب البنك» من بطاقة كل بنك أو خزينة، وتحديد فترة زمنية أو عرض جميع الحركات. يشمل الكشف دفعات العملاء، وسداد الموردين، والمصروفات العامة، ورد مبالغ المرتجعات إلى البنك، والتحويلات الداخلية والسندات العكسية؛ ويعرض الوارد والمنصرف والرصيد الجاري وإجمالي الفترة، مع إمكانية الطباعة. يُستنتج رصيد أول الفترة من الرصيد الحالي والحركات المسجلة، لذلك فإن أي تغييرات يدوية سابقة على رصيد البنك لا تظهر كحركة مستقلة في الكشف.

### التحويلات الداخلية بين البنوك والخزائن

للمدير فقط: زر «تحويل بين الحسابات» أو «تحويل من هذا الحساب» داخل تبويب البنوك والخزائن. اختر حساب المصدر والمستلم، والمبلغ (منزلتان عشريتان كحد أقصى)، والتاريخ غير المستقبلي، والمرجع والملاحظات الاختياريين. تعرض المعاينة رصيد الحسابين قبل التحويل وبعده؛ يُراجع الخادم الرصيد الفعلي عند التنفيذ ويخصم ويضيف ويحفظ السند في معاملة واحدة دون تغيير إجمالي أموال المنشأة أو تسجيل إيراد أو مصروف. يُحفظ رقم موحد مثل `TRF-00000001` واسم المنفذ وأسماء الحسابات وأرصدة لحظة التنفيذ.

يعرض السجل البحث والفترة والحساب وحالة التنفيذ؛ تطبع السندات ببيانات الحسابين ومبلغ التحويل ومساحات التوقيع. يظهر السند نفسه كتحويل صادر في كشف المصدر ووارد في كشف المستلم. لا يمكن تعديل أو حذف سند صادر؛ استخدم «عكس التحويل» مع سبب إلزامي. ينشئ العكس سندًا جديدًا بتاريخ ووقت التنفيذ الحاليين مرتبطًا بالأصل، بشرط توفر المبلغ في الحساب المستلم، ويحفظ السندين في الكشوف حتى بعد عكس الأصل. لا يمكن عكس السند العكسي أو عكس الأصل مرتين.

تحمل كل محاولة معرّفًا ثابتًا يمنع تكرار الخصم عند النقر المتكرر أو إعادة الطلب. عند انقطاع الاتصال أو وصول استجابة غير مؤكدة، يبقى النموذج مقفلًا مع زر «التحقق وإعادة المحاولة دون تكرار» بالمعرّف نفسه؛ لا تنشئ تحويلًا بديلًا قبل التحقق من السجل. الرسوم البنكية ليست جزءًا من التحويل: سجّلها كمصروف عام مستقل مع رقم سند التحويل في المرجع.

تتطلب الميزة تحديث الخادم والمحطة معًا؛ تُنشأ جداول التحويلات وفهارسها وعلاقاتها تلقائيًا عند بدء الخادم المحدث. خذ نسخة احتياطية من Access بعد إيقاف الخدمة وقبل التحديث. لا يتصل تطبيق المحطة بملف Access مباشرة، ولا تسمح واجهة قاعدة البيانات العامة بالوصول إلى سجلات التحويلات.

تظهر حركة «دفعات العملاء» في كشف البنك برقم سند القبض نفسه، مثل `REC-00001`، بدل معرّف قاعدة البيانات الطويل. يمنح الخادم الدفعات الجديدة رقمًا متسلسلًا محفوظًا، ويملأ أرقام الدفعات القديمة الناقصة عند بدء التشغيل بحسب ترتيب إنشائها، مع الحفاظ على الأرقام الموجودة والمبالغ والأرصدة والتواريخ. التسلسل موحد لجميع البنوك والعملاء ولا يتغير بتصفية الكشف أو تصويب الدفعة. حدّث الخادم وأعد تشغيله لتفعيل ترقيم الدفعات القديمة والجديدة.

تُحفظ قائمة الأسعار المخصصة للعميل في نسخة سطح المكتب عبر اتصال الخادم المُعدّ في `server.json`، وفي المتصفح عبر واجهة العملاء. تُحمّل الأسعار المحفوظة مجددًا مع العميل وتُستخدم في البيع، وتُعرض رسالة السبب عند فشل الحفظ. السعر صفر صالح؛ مسح خانة السعر وحفظ القائمة يلغي تخصيص ذلك الصنف ويعيد تطبيق قواعد التسعير الافتراضية. تُحفظ القائمة كاملة في معاملة واحدة. تعرض بيانات كل صنف الاسم والكود والنوع والمقاس والدرجة واللون والمورد والطول والوزن وسعر الكيلو في صف واحد مع تمرير أفقي عند الحاجة، وتُرتب الأصناف ذات الأسعار المخصصة أعلى القائمة. يطبع زر «طباعة الأصناف المخصصة» الأصناف المسعرة للعميل وحدها مع بياناتها وأسعارها. يتطلب الإصلاح إعادة بناء تطبيق المحطة وتحديث الخادم معًا.

في تبويبي العملاء والموردين، اختيار «من / إلى» يعرض أصحاب الحركات في الفترة فقط، ويحسب البطاقات والإجماليات وطباعة الجدول من فواتير ودفعات الفترة دون أرصدة سابقة. يشمل تاريخ «إلى» اليوم كاملًا. يرث كشف الحساب الفترة المختارة مع إمكانية تعديلها داخله، وتظهر الفترة في الطباعة. «عرض الكل» يعيد العرض غير المقيّد بالفترة. لا تغيّر الفلترة الأرصدة الأصلية في نماذج تعديل البيانات.

تُطبّق الفترة والبحث معًا أيضًا على فواتير المشتريات والمصروفات العامة وسندات الصرف وسندات القبض والفواتير وعروض الأسعار. تعتمد الصفوف والإجماليات وزر «طباعة الجدول» على القائمة المفلترة نفسها، وتظهر الفترة في التقرير المطبوع. تعتمد الحركة على تاريخها المسجل، أو تاريخ إنشائها عند غيابه. تظل طباعة الفاتورة أو السند الفردي كما هي. لا تشمل الفلترة الزمنية المخزون والبنوك لأنهما يعرضان أرصدة حالية ولا يحتويان على اختيار فترة.

تظهر كشوف حساب العملاء والموردين داخل التطبيق بالشكل الداكن القديم: جدول مستقل للفواتير وجدول للسندات، مع أزرار فتح وطباعة كل مستند. يحتفظ زر «طباعة الكشف» بالتنسيق الورقي الجديد ذي الجدول الموحد والرصيد المتحرك والإجماليات. يشترك العرض والطباعة في الفترة والبيانات نفسها، وتبقى مبالغ شراء المورد للمدير فقط.

فتح فاتورة شراء من كشف المورد يعرض بنودها وبيانات الأصناف كما في تبويب المشتريات، مع الحفاظ على صلاحية عرض المبالغ للمدير فقط، سواء في المتصفح أو تطبيق سطح المكتب.

يمكن إدخال «رقم استلام المخزن» اختياريًا عند إنشاء فاتورة شراء أو تعديلها، مستقلًا عن رقم فاتورة التوريد. يُحفظ الرقم مع الفاتورة ويظهر في معاينتها وطباعتها، بما فيها الفواتير المفتوحة من كشف المورد وتقارير الأصناف. يُضاف الحقل تلقائيًا عند بدء الخادم المحدث، وتبقى الفواتير القديمة دون رقم حتى إدخاله. خذ نسخة احتياطية من Access قبل تحديث الخادم.

### كشف حركة الأصناف

يعرض تبويب الجرد الباركود والنوع والدرجة والمورد والطول والوزن بجانب تعريف الصنف في قائمة الاختيار وجدول العد، ويشمل البحث هذه البيانات. الحقول غير المسجلة تظهر بوضوح بدل إخفائها. لا تظهر الأسعار أو التكلفة أو الضريبة أو حدود المخزون ضمن بيانات الصنف؛ تبقى حسابات قيمة النقص والزيادة والصافي وتكلفة تقييم الجرد المثبّتة كما هي. هذه مواصفات بطاقة الصنف الحالية، ولا تغيّر وصف الجرد المحفوظ. يلزم تحديث الخادم والمحطة معًا لتحميل وعرض الحقول الإضافية.

تبويب «تقارير الأصناف» يعرض تفاصيل الأصناف في الفواتير الصادرة، دون أزرار إضافية في بطاقات العملاء والموردين. اختر مبيعات العملاء أو مشتريات الموردين، والطرف أو جميع الأطراف، والفترة، والصنف، أو ابحث بالكود والاسم والمواصفات. العرض التفصيلي مرتب: الكود، الصنف والمواصفات، التاريخ، العميل أو المورد، الحركة، الكمية، سعر الوحدة، قبل الضريبة، الضريبة، الإجمالي، المستند. تتبع الطباعة الترتيب نفسه. العرض الملخص يجمع حسب معرّف الصنف مع كمية البيع أو الوارد والمرتجع والصافي وعدد الفواتير والمرتجعات دون تكرار المستند للصنف. لا تُجمع كميات الأصناف المختلفة في إجمالي عام.

تُقرأ الأسعار والضرائب والإجماليات المحفوظة في بنود المستند، ولا تُستخدم الأسعار الحالية ولا تدخل عروض الأسعار في الكشف. مرتجعات البيع اختيارية، وتظهر كحركات سالبة بتاريخ إصدار المرتجع، حتى إذا كانت الفاتورة الأصلية خارج الفترة. يمكن فتح الفاتورة أو إشعار المرتجع بالضغط على رقمه وطباعته، وطباعة الكشف التفصيلي أو الملخص بالفلاتر والفترة والإجماليات نفسها. الكشف للقراءة فقط ولا يغيّر المخزون أو الحسابات. زر «تحديث الكشف» يعيد تحميل المستندات ويظهر فشل الاتصال صراحةً بدل عرض كشف فارغ.

المدير يراجع المبيعات والمشتريات بقيمها؛ الكاشير يراجع المبيعات فقط؛ أمين المخزن يراجع المشتريات بكمياتها دون الأسعار والضرائب والمبالغ في الشاشة أو الطباعة أو الفاتورة المفتوحة. يستخدم الكشف مسارات المستندات الحالية في المتصفح وجسور Electron الحالية في المحطة، دون جداول جديدة. العملاء النقديون غير المرتبطين بحساب يظهرون ضمن خيار مستقل، مع اسم كل فاتورة في التفاصيل.

يمكن إنشاء مرتجعات متعددة لكل فاتورة مبيعات من قائمة الفواتير. يحدد المستخدم الصنف والكمية في كل مرة، ويمنع النظام تجاوز الكمية الأصلية بعد جمع المرتجعات المعتمدة السابقة. تُحسب القيمة والضريبة من بيانات الفاتورة، وتعود الكميات إلى المخزون ضمن معاملة واحدة. تُخصم قيمة المرتجع من مديونية العميل أولًا؛ ويُرد أي فائض نقدًا أو من بنك مختار، مع إظهار المرتجع ورد المبلغ في كشف العميل، أرصدة العملاء وتقارير صافي المبيعات، وطباعة إشعار مرتجع مرتبط بالفاتورة. لا يسمح بحذف فاتورة لها مرتجعات. يتطلب التشغيل تحديث كود خادم Access وإعادة تشغيله، ثم إعادة بناء تطبيق المحطة؛ تُنشأ جداول المرتجعات الجديدة تلقائيًا دون تعديل الفواتير السابقة.

### سندات الخصم المستقلة

من تبويب «الخصومات»، سجّل **خصمًا مسموحًا به للعميل** أو **خصمًا مكتسبًا من المورد**، باختيار الطرف والمبلغ والسبب اختياريًا. يستطيع المدير تسجيل النوعين، والكاشير خصم العميل، وأمين المخزن خصم المورد. يتأكد الخادم من جلسة المستخدم وصلاحيته الحالية ومن الرصيد المستحق لحظة الحفظ، ويرفض الخصم الزائد أو غير الموجب أو الذي يتجاوز منزلتين عشريتين. تُحفظ العملية وتحديث رصيد المورد في معاملة واحدة، ولا تتكرر إذا أُعيد إرسال الطلب نفسه بعد انقطاع الاتصال.

السند تسوية مستقلة على الحساب، وليست خصمًا على فاتورة محددة أو نسبة الخصم الموجودة في بطاقة العميل. يخفض رصيد الطرف، ويظهر في كشفه وسجل الخصومات وتقارير العملاء والموردين مع إمكانية الطباعة. لا يغيّر الخزينة أو البنك أو المخزون أو قيمة الفاتورة أو الضريبة، ولا ينشئ قيد أستاذ عام. لا يمكن تعديل السند أو حذفه بعد حفظه؛ تفريغ بيانات التجربة المؤكد استثناء يحذف سندات الخصم مع بقية الحركات. راجع المحاسب قبل اعتماد السند وأي معالجة محاسبية أو ضريبية لازمة.

لا يُعكس سند خصم العميل تلقائيًا عند المرتجع، بل يدخل في حساب الرصيد والمبلغ الواجب رده. مثلًا: فاتورة غير مسددة بقيمة 100 وخصم مستقل بقيمة 20 ثم إرجاع كامل الفاتورة ينتج عنه رد 20 للعميل. راجع المحاسب قبل اعتماد المرتجعات التي توجد معها خصومات.

خذ نسخة احتياطية من ملف Access بعد إيقاف الخدمة والمحطات، ثم حدّث خادم البيانات ومحطات البيع معًا وأعد تشغيلها؛ يُنشأ جدول السندات تلقائيًا دون استبدال البيانات. شغّل خدمة خادم واحدة فقط على ملف Access المحلي، ولا تشارك الملف مباشرة بين محطات أو خدمات خادم مستقلة؛ تنظيم معاملات الخصم داخل عملية الخادم الواحدة لا ينسق عمليات خادم متعددة.

يمكن لمدير النظام فقط تصويب سند القبض من زر «تصويب» في قائمة الدفعات، بتعديل العميل أو البنك/الخزينة أو المبلغ أو التاريخ أو المرجع والملاحظات. يُحفظ التعديل وسجل القيم قبل التصويب وبعده ضمن معاملة واحدة، ويُعدّل رصيد البنك القديم والجديد بالتزامن. يتطلب التصويب جلسة مدير نظام صالحة، ويُحفظ سجل التصويبات في Access عبر معاملات ODBC للنصوص الطويلة. عند تحديث الخادم، تؤخذ نسخة احتياطية ويُوقف الخادم ثم يعاد تشغيله؛ حدّث تطبيقات المحطات أيضًا.

يظهر زر «تعديل» لمدير النظام فقط في قوائم فواتير المشتريات والمصروفات العامة وسندات الصرف، وكذلك في معاينة فاتورة الشراء وسند الصرف. يمكن تعديل المورد والأصناف والكميات والتكاليف ونوع فاتورة الشراء ورقمها وتاريخها، أو تغيير التصنيف والبنك والمبلغ والتاريخ والمرجع والملاحظات للمصروف والسند بحسب نوعه. تُسوّى فروق المخزون ومديونية الموردين وأرصدة البنوك ضمن معاملة واحدة دون إنشاء مستند جديد أو تغيير رقم سند الصرف أو المصروف. يمنع تخفيض كميات الشراء عندما لا يكفي المخزون المتاح، ولا يغيّر تعديل فاتورة قديمة أسعار الشراء والبيع الحالية في بطاقة الصنف. إذا تغير المستند بعد فتحه، يُرفض الحفظ ويجب إغلاق النموذج وتحديث القائمة قبل إعادة التعديل. تبقى الطباعة والكشوف والفلاتر مرتبطة بالبيانات المعدلة. يتطلب التفعيل تحديث الخادم وإعادة تشغيله وإعادة بناء تطبيقات المحطات؛ لا يتطلب إنشاء قاعدة بيانات جديدة.

يظهر سطر «رصيد أول المدة» قبل حركات كشف العميل والمورد في المعاينة والطباعة، حتى عند اختيار فترة أو عدم وجود حركات. يعرض الرصيد الافتتاحي المحفوظ عند تأسيس الحساب، وليس الرصيد الحالي أو المتبقي، ولا يمثل رصيدًا متراكمًا محسوبًا قبل تاريخ «من». في الكشف التفصيلي، «إجمالي الفواتير والرصيد الافتتاحي» يجمع الافتتاحي مرة واحدة مع فواتير الفترة، و«إجمالي المطلوب» يطرح سدادات الفترة منه. تتطابق المعاينة والطباعة، بينما تبقى إجماليات قوائم التبويبات للفترة فقط كما سبق.

يُحفظ الرصيد الافتتاحي للمورد مستقلًا عن رصيده الحالي؛ لا تغيّره المشتريات أو الدفعات. تعديل الافتتاحي يغيّر الرصيد الحالي بمقدار الفرق فقط ويحافظ على الحركات السابقة. عند تحديث الخادم، يُضاف الحقل تلقائيًا لقواعد Access القديمة وتُستخرج قيمته مرة واحدة من الرصيد الحالي ناقص جميع المشتريات زائد جميع المدفوعات، دون تغيير الرصيد الحالي أو الحركات. إذا كانت الأرصدة الحالية قد عُدّلت يدويًا سابقًا، راجع القيم المستخرجة وصحّحها من بطاقة المورد. أنشئ نسخة احتياطية وأوقف المحطات قبل تحديث الخادم، ثم حدّث جميع المحطات معه.

تصميم كشوف العملاء والموردين موحّد بين المعاينة والطباعة: جدول واحد يبدأ بالرصيد الافتتاحي، ثم الفواتير والسندات بترتيب زمني تصاعدي، ثم الإجماليات كسطور في نهايته. يعرض الجدول المدين والدائن والرصيد بعد كل حركة، مع بيانات المستند والبنك والملاحظات. يمكن فتح المستند من رقمه في المعاينة، وتُخفى الأزرار في الطباعة. يستخدم التصميم ألوانًا هادئة وحدودًا أفقية رفيعة، ويكرر رأس الجدول عند تعدد الصفحات دون تكرار الإجماليات. تبقى صلاحيات عرض مبالغ فواتير الموردين كما هي.

تستخدم جميع المطبوعات قالب كشف الحساب نفسه فعليًا، بنفس الخط والألوان ورأس الجدول وسطور الإجماليات، بما فيها فواتير المبيعات وعروض الأسعار والمشتريات وسندات القبض والصرف وجداول التبويبات. تستخدم المستندات صفوفًا مضغوطة لاستيعاب مزيد من البيانات، وتعرض المعاينة عرض مساحة الطباعة الفعلي بالمليمتر. جميع المطبوعات A4 رأسي، مع هامش أيسر موسّع 20 مم في جميع النماذج حتى يبقى التخريم لحفظ الأوراق في الملفات بعيدًا عن البيانات؛ لا يتحول أي تقرير تلقائيًا إلى الوضع الأفقي. تُلفّ بيانات الجداول العريضة داخل الأعمدة بخط أصغر دون حذف بيانات أو قصّ الأعمدة. تُعرض إجماليات الفاتورة كسطور في جدول الأصناف، مع الحفاظ على الضرائب ورمز QR والتحويل من عرض سعر، وعلى التوقيعات وكعب سند القبض والصرف. في كشف الحساب أُلغي عمود «العملية» وحُذف نوع الفاتورة وتفاصيل الضريبة من البيان؛ تبقى بيانات إذن الاستلام والمستلم والبنك والملاحظات، دون تغيير الحسابات.

تُخفى أرقام التسجيل الضريبي والسجل التجاري من جميع المطبوعات ومعايناتها، بما فيها بيانات البائع والعميل والمورد وتقرير الموردين. تُسمّى الفواتير «فاتورة» فقط دون وصفها بالضريبية أو غير الضريبية، وتبقى عروض الأسعار مميزة باسم «عرض سعر». لا يحذف ذلك البيانات المحفوظة ولا يغيّر احتساب الضرائب أو مبالغها أو رمز QR.

يعرض رمز QR عند مسحه نصًا يتضمن رقم الفاتورة وتاريخ إصدارها وإجماليها شامل الضريبة وقيمة الضريبة. لا يفتح الرمز موقعًا ولا يتصل بجهة ضريبية؛ وهو ليس رمزًا ضريبيًا معتمدًا.

## التطوير

تتوفر أزرار الطي والفتح والتثبيت أعلى القائمة الرئيسية اليمنى وقائمة المبيعات والعروض اليسرى. عند طي القائمة اليمنى تبقى أيقونات التنقل ظاهرة وقابلة للنقر مع الاحتفاظ بأسمائها لقارئ الشاشة؛ تتمدد بعد بقاء المؤشر عليها ثانيتين، ويُلغى الانتظار عند المغادرة. تفتح القائمة اليسرى فور المرور فوق شريطها دون انتظار. القائمتان مثبتتان افتراضيًا؛ طي القائمة يلغي تثبيتها، وتظهر القائمة غير المثبتة فوق المحتوى دون حجز عرض وتُطوى عند مغادرة المؤشر. يمكن فتحهما بالنقر وتثبيتهما مجددًا. تتحرك القوائم خلال 300 مللي ثانية بتدرج هادئ مع احترام إعداد تقليل الحركة، دون مسح السلة أو الحقول.

عند ظهور `linkedQuotationId is not defined` أثناء إصدار فاتورة من محطة، حدّث تطبيق Electron وأعد تشغيله: النسخ القديمة قد تستخدم متغير ربط عرض السعر دون تعريفه. لا يكفي تحديث الخادم لإصلاح الكود المجمّع داخل المحطة. تُصدر الفاتورة العادية دون ربط عرض سعر؛ وعند التحويل، يُعلَّم العرض «تم التحويل» فقط بعد حفظ فاتورة فعلية ضمن المعاملة نفسها.

تعرض بطاقات الأصناف في البيع والمخزون بياناتها وسعر البيع بخط 11 بكسل والاسم بخط 14 بكسل. يظهر الكود والاسم والنوع في أعلى البطاقة فوق الصورة، وبقية المواصفات في صف واحد تحتها بمحاذاة اليمين دون عناوين مثل «اللون» و«المورد»، مع تمرير أفقي عند ضيق البطاقة دون حذف المواصفات. تظهر الاختصارات بجانب القيم: م للمقاس، ط للطول، ز للوزن، وش لسعر الشراء ون للنسبة للمستخدم الرئيسي فقط. يعرض سعر الشراء والنسبة مقربين لأقرب عدد صحيح دون تغيير القيم المحفوظة أو الحسابات، وتبقى دقة المقاسات والأطوال والأوزان وسعر البيع كما هي. تتلون خلفية خانة اللون بلون الصنف مع نص متباين؛ تبقى القيم غير اللونية مثل «مقاوم» محايدة. يظهر سعر البيع والمخزون وزر الإضافة للسلة في صف واحد مستقل أسفل التفاصيل في شاشة البيع، مع التفاف نص السعر والمخزون داخل خانتيهما عند ضيق البطاقة دون إخفاء زر السلة. تستخدم بطاقات نقطة البيع عرضًا أدنى 220 بكسل بدلًا من 230 بكسل، مع حد أقصى أربعة منتجات في الصف مهما اتسعت المساحة. تتسع أربعة منتجات عند توفر 916 بكسل مع الفواصل، ويقل عدد الأعمدة تلقائيًا في المساحات الأضيق لمنع ضغط البيانات. تبقى بطاقات المخزون بعرض أدنى 320 بكسل متى سمحت الشاشة. يستطيع المستخدم الرئيسي (ADMIN) تغيير الصورة من زر الكاميرا في البطاقة واختيار ملف JPG أو PNG أو WebP أو GIF من الكمبيوتر بحجم أقصى 2 ميجابايت. تُحفظ الصورة داخل بيانات الصنف لتظهر بعد إعادة التشغيل وعلى المحطات الأخرى، دون تغيير الأسعار أو المخزون أو المورد أو بقية المواصفات. لا يظهر زر رفع الصور لباقي المستخدمين.

في رأس سلة المبيعات، يظهر حقل العميل في السطر الأول مستفيدًا من المساحة التي كان يشغلها نوع الفاتورة. ينتقل اختيار «فاتورة ضريبية / فاتورة» إلى السطر الثاني بجانب اسم المستلم، ويقتصر حقل رقم إذن الاستلام على ربع عرض السطر.

تظهر بنود سلة البيع والفاتورة وعرض السعر بحسب ترتيب إضافتها، دون إعادة فرز حسب الكود أو المقاس أو اللون. يُحفظ ترتيب البنود الجديدة في قاعدة البيانات ليبقى كما هو عند إعادة فتح الفاتورة وطباعتها أو تحويل عرض السعر إلى فاتورة. زيادة كمية صنف موجود لا تغيّر موقعه؛ حذفه وإضافته من جديد يضعه في نهاية السلة. يتطلب تثبيت الترتيب بعد إعادة التشغيل تحديث الخادم؛ يُضاف حقل ترتيب البنود تلقائيًا دون تغيير المبالغ أو المخزون. لا يمكن استعادة ترتيب الإدخال الأصلي للفواتير القديمة التي لم تحفظ هذا الترتيب.

يستطيع المدير تعديل عرض السعر بعد إصداره من قائمة الفواتير أو معاينة العرض. يقتصر التعديل على إضافة البنود وإزالتها والكميات والأسعار، مع الحفاظ على ترتيبها ورقم العرض وتاريخ إصداره والعميل ونوع الفاتورة وبيانات الاستلام. تُحدّث الإجماليات والطباعة في المستند نفسه دون إنشاء عرض جديد أو تغيير المخزون أو التسليمات أو أرصدة الحسابات. تُحفظ نسبة ضريبة البنود السابقة وتُستخدم ضريبة بطاقة الصنف للبنود الجديدة، مع إبقاء العرض غير الضريبي بلا ضريبة. يمنع الخادم تعديل الفواتير والعروض المحوّلة أو نسخة قديمة من العرض، ويتحقق من صلاحية المدير من قاعدة البيانات. يتطلب التفعيل تحديث الخادم والمحطات؛ لا يتغير عرض السعر عند إلغاء النموذج أو فشل الحفظ.

### تعديل بيانات فاتورة المبيعات بعد إصدارها

يظهر للمدير فقط زر «تعديل بيانات الفاتورة» في قائمة الفواتير ومعاينة الطباعة للفواتير الصادرة. يتيح تغيير اسم المستلم ورقم إذن الاستلام (أو مسحهما)، واختيار العميل المرتبط بالفاتورة. يمكن إدخال اسم العميل النقدي للفواتير دون حساب مرتبط؛ أما اسم العميل المسجل فيؤخذ من حسابه، ولا يعيد هذا الإجراء تسمية حساب العميل.

اختيار عميل آخر ينقل ارتباط الفاتورة وأثرها في كشف الحساب إلى العميل الجديد، وليس تغيير الاسم في الطباعة فقط. **يُمنع نقل العميل إذا كانت للفاتورة أي مرتجعات، أو للعميل الأصلي أي دفعات أو سندات خصم حتى لو كانت تخص فواتير أخرى.** يبقى تعديل المستلم وإذن الاستلام للعميل نفسه مسموحًا. تشمل القاعدة النقل من عميل مسجل إلى نقدي أو العكس؛ لا تُنقل دفعات أو خصومات أو مرتجعات أو تُعدّل أرصدة بنوك.

عند النقل تُخصم كميات الأصناف من «المسلّم» في حصص الأسقف الموجودة للعميل الأصلي وتضاف إلى الحصص الموجودة للعميل الجديد في المعاملة نفسها، دون إنشاء حصص جديدة أو تغيير المخزون. تُجمع البنود المكررة للصنف، ويُرفض النقل عند وجود رصيد تسليم غير متسق أو تجاوز سعة الحقل. لا تُفرض حدود جديدة للحصة تتجاوز سلوك إصدار الفاتورة الحالي. تنتقل قيمة الفاتورة بين كشفي الحساب تلقائيًا من ارتباطها بالعميل، ولا يتغير الرصيد الافتتاحي لأي عميل.

تظل الأصناف وترتيبها وأسعارها والضريبة والإجماليات ورمز QR ورقم الفاتورة وتاريخ إصدارها دون تغيير. يمنع الخادم تعديل عروض الأسعار بهذه الواجهة أو تعديل نسخة قديمة من الفاتورة، ويتحقق من دور المدير الحالي داخل معاملة قابلة للتراجع. عند فشل الحفظ يبقى النموذج مفتوحًا بالمدخلات، وعند النجاح تُحدّث قائمة الفواتير والعملاء ومعاينة الطباعة. يتطلب التفعيل تحديث الخادم والمحطة معًا.

### تسعير وأرباح عروض الأسعار

للمدير فقط: زر «تسعير وأرباح عرض السعر» في نقطة البيع يحلل بنود السلة ويتيح حفظ عرض جديد بأسعار تفاوضية دون تغيير أسعار السلة عند الإلغاء أو أسعار المخزون. وتظهر اللوحة نفسها عند تعديل عرض صادر غير محوّل من قائمة الفواتير أو معاينته.

تُقرأ **تكلفة الصنف الحالية من بطاقة المخزون** عبر جلسة المدير، دون تخزين تكلفة تاريخية داخل العرض. إعادة فتحه أو الضغط على «تحديث التكلفة الحالية» يقرأ التكلفة الجديدة ويعيد حساب الربح فقط، ولا يغيّر أسعار البيع تلقائيًا. تعتمد التكلفة على حقل سعر التكلفة بالمخزون الذي يتحدث عند تسجيل الوارد ويمكن للمدير تعديله، ولا يجري التحليل بحثًا عن فاتورة شراء قديمة أو حساب متوسط للوارد. يعرض التحليل تكلفة وربح الوحدة وربح كل بند والإجمالي قبل الضريبة والمصروفات العامة، لذلك فهو ربح إجمالي تقديري وليس صافي ربح المنشأة.

يمكن تعديل سعر البيع مباشرة، أو تحديد ربح الوحدة بالجنيه، أو نسبة زيادة على التكلفة. النسبة الموحدة 30% تعني أن تكلفة 100 تصبح سعر بيع 130، لا هامش ربح 30% من المبيعات. تُعرض معاينة بأسعار البنود والربح الناتج قبل التطبيق. خيار تثبيت سعر الصنف يستثنيه من التوزيع الجماعي فقط ويترك تعديله اليدوي ممكنًا. ويمكن إدخال ربح إجمالي مستهدف، فيُخصم ربح الأصناف المثبتة ويوزّع الباقي بحسب تكلفة وكميات الأصناف غير المثبتة؛ تُقرّب أسعار الوحدات لمنزلتين، ويُعرض فرق الربح الفعلي عن الهدف صراحة.

التكلفة الصفرية أو غير المتاحة لا تُعتبر ربحًا كاملًا: تظهر «غير متاح»، ويُمنع التوزيع الجماعي حتى استكمال تكلفة جميع البنود. يمكن حفظ الأسعار اليدوية مع تأكيد عدم اكتمال التحليل. تظهر البنود الأقل من التكلفة بالأحمر، ويتطلب تطبيق أسعار خاسرة أو حفظها تأكيد المدير. قبل حفظ العرض يعاد التحقق من التكلفة الحالية على الخادم لأغراض التحذير؛ قد تتغير التكلفة بعد ذلك فلا تُثبّت داخل المستند. لا تظهر اللوحة أو التكاليف أو الأرباح في طباعة عرض السعر للعميل، ولا تتغير الضرائب أو المخزون نتيجة تحليل الربح. يتطلب التفعيل تحديث الخادم والمحطة معًا.

تستخدم صور بطاقات نقطة البيع وإدارة المخزون مساحة العرض نفسها بارتفاع 128 بكسل، مع احتواء الصورة كاملة والمحافظة على أبعادها دون قص أو تكبير عند تمرير المؤشر. تبقى عروض البطاقات وعدد الأعمدة كما هي.

تظهر المبالغ والأسعار والأرصدة بفواصل الآلاف والملايين في الشاشات والسلة والسندات وكشوف الحساب والطباعة، مثل `1,234,567.89`. تعرض حقول إدخال المبالغ الفواصل أيضًا، وتقبل لصق مبلغ منسق أو إدخاله بالأرقام العربية، بينما تظل القيم المرسلة للحفظ والحسابات أرقامًا دون فواصل. تبقى دقة الأسعار المخصصة والقيم المحفوظة كما هي؛ لا تُضاف الفواصل إلى أكواد الأصناف وأرقام المستندات والهواتف أو النسب.

### قوائم النوع واللون والدرجة

- تُحفظ القوائم في قاعدة البيانات (جدول `ProductOption`) فتُشارك بين كل الأجهزة والمستخدمين، وتُزرع تلقائيًا عند أول تحميل من القيم الافتراضية وقيم الأصناف الموجودة.
- في نموذج الصنف يظهر للمدير فقط زر «+» لإضافة عنصر جديد (يُختار تلقائيًا بعد الحفظ) وزر إدارة القائمة للتعديل والحذف؛ باقي المستخدمين يستخدمون القوائم فقط.
- لا يُقبل اسم مكرر (دون اعتبار الفراغات الزائدة وحالة الأحرف). تعديل الاسم يحدّث كل الأصناف المرتبطة، والحذف مرفوض إن كان الخيار مستخدمًا في أي صنف. أنواع النظام الأساسية لا تُعدَّل ولا تُحذف لارتباطها بالصور والأوصاف.
- يحتاج تفعيل الميزة تحديث الخادم والمحطات معًا.

### تفريغ بيانات التجربة قبل التشغيل الرسمي

**من داخل البرنامج (للمدير فقط):** تبويب «تفريغ بيانات التجربة» يعرض عدد السجلات التي ستُحذف وجداول البنوك والموردين والعملاء والأصناف بقيمها الحالية، وتعدّل المدير عمود «القيمة بعد التفريغ» (رصيد البنك، الرصيد الافتتاحي للمورد والعميل، كمية الصنف الفعلية) أو يضغط «تصفير الكل». يتطلب التنفيذ كلمة مرور حساب المدير وكتابة كلمة «تفريغ». يُنشأ تلقائيًا نسخة احتياطية من ملف قاعدة البيانات بجوار الأصل على جهاز الخادم ويظهر مسارها بعد النجاح. أغلق كل المحطات الأخرى قبل التنفيذ. يتطلب تحديث الخادم والمحطات معًا.

**بديل بسطر الأوامر:** يحذف السكربت [reset-for-production.js](scripts/reset-for-production.js) الحركات فقط (فواتير ومرتجعات وعروض أسعار ودفعات وسندات خصم ومشتريات ومصروفات وسداد موردين وتحويلات وجرد) ويُبقي الأصناف والموردين والعملاء والبنوك والمستخدمين وتصنيفات المصروفات وخيارات الأصناف وسقوف العملاء (مع تصفير الكمية المستلمة) وكلمة مرور اعتماد الجرد.

1. أوقف الخادم وكل المحطات. يرفض السكربت العمل إن كانت قاعدة البيانات مفتوحة، وينشئ نسخة احتياطية تلقائيًا بجوار الملف قبل أي حذف.
2. صدّر القالب: `node scripts/reset-for-production.js --db <الملف.accdb> --template opening.csv`، ثم عدّل عمود `value` بالأرصدة الحقيقية يوم البدء: رصيد البنك، والرصيد الافتتاحي للمورد والعميل، وكمية الصنف الفعلية من الجرد.
3. عاين دون تغيير: `node scripts/reset-for-production.js --db <الملف.accdb> --opening opening.csv`
4. نفّذ: `node scripts/reset-for-production.js --db <الملف.accdb> --opening opening.csv --execute --confirm RESET`

سجل غير موجود في الملف يرفضه التنفيذ إلا مع `--allow-missing` فتبقى قيمه الحالية (ويُعاد رصيد المورد إلى افتتاحيه). جرّب الخطوات على نسخة من الملف أولًا. بعد التفريغ تبدأ ترقيمات المستندات من جديد.

### تصنيفات المصروفات

- أُلغي زر «إدارة التصنيفات»؛ يظهر للمدير فقط في حقل «التصنيف» داخل نموذج المصروف العام زر «+» للإضافة وزر لإدارة القائمة (تعديل الاسم وحذف التصنيف غير المستخدم)، والتصنيف الجديد يُختار تلقائيًا.
- تعديل الاسم يظهر في كل المصروفات المرتبطة؛ الحذف مرفوض إن كان التصنيف مستخدمًا في أي مصروف، ولا يُقبل اسم مكرر.
- الإضافة والتعديل والحذف تتحقق من الجلسة والدور في الخادم، ولم يعد إنشاء تصنيف متاحًا دون جلسة مستخدم.

### جرد المخزون

يظهر تبويب «جرد» لمدير النظام وأمين المخزن فقط. يمكن اختيار أصناف محددة أو جميع الأصناف، وإدخال الكميات الفعلية ومراجعة الفرق عن رصيد الدفتر وحفظ مسودة جزئية دون تغيير المخزون. الخانة الفارغة تعني أن الصنف لم يُعدّ بعد، أما الصفر فيعني عدم وجود كمية فعلية. تُرقّم المستندات تلقائيًا مثل `STK-00000001` وتبقى المسودات والجرد المعتمد في السجل مع اسم المُعدّ والمُعتمد ووقت الاعتماد.

الاعتماد للمدير فقط، ويتطلب كلمة مرور مستقلة خاصة بالجرد. يعيّنها المدير أو يغيّرها من داخل التبويب بعد إدخال كلمة مرور حسابه؛ يجب ألا تقل عن 8 أحرف، وتُحفظ مشتقة بخوارزمية scrypt مع ملح عشوائي، لا كنص صريح. لا تُعرض كلمة المرور أو مشتقتها في بيانات الجرد. يعمل الاعتماد عبر جلسة المستخدم الموقعة في الويب وElectron، وتُراجع صلاحيات الحساب من قاعدة البيانات عند كل إجراء.

يجب حفظ التعديلات وإكمال عدّ جميع الأصناف المختارة قبل الاعتماد. تُحدّث كمياتها فقط، دون تغيير الأسعار أو التكاليف أو أرصدة الأصناف غير المختارة، ضمن معاملة واحدة مع تسجيل الاعتماد؛ لا يمكن اعتماد المستند مرتين أو تعديله بعد اعتماده. إذا تغيّر رصيد صنف بعد بدء الجرد، يُرفض الاعتماد بدل الكتابة فوق حركة أحدث. استخدم «تحديث أرصدة الدفتر» في المسودة المحفوظة؛ يُفرغ العد الفعلي للأصناف المتغيرة فقط لإعادة عدّها، ثم احفظ واعتمد. ينبغي تنسيق توقيت العد مع حركة المخزن؛ لا يوقف الجرد البيع أو الشراء.

يتطلب هذا التبويب نشر تحديث الخادم والمحطات وإعادة تشغيلها. ينشئ الخادم جداول الجرد وإعداد كلمة مروره تلقائيًا في قاعدة Access عند التشغيل، دون تعديل الأرصدة الحالية. لا يغيّر تحديث كلمة مرور الجرد كلمة مرور تسجيل الدخول.

إذا ظهرت رسالة «انتهت الجلسة» على المحطة مباشرة بعد تسجيل الدخول بينما يعمل الجرد على جهاز التطوير، فتحقق من تحديث خادم البيانات الذي تتصل به المحطة فعلًا، لا ملف تثبيت المحطة فقط. الخادم القديم قد يقبل تسجيل الدخول دون إصدار `sessionToken` الذي تتطلبه عمليات الجرد. انشر إصدار الخادم المتوافق وأعد تشغيل خدمته، مع الحفاظ على قاعدة Access وإعدادات الاتصال الحالية، ثم سجّل الخروج والدخول مجددًا على المحطة. يرفض العميل الآن استجابة تسجيل الدخول التي لا تحتوي على جلسة ويطلب تحديث الخادم بوضوح. إذا استمر رفض جلسة جديدة بعد تحديث الخادم، فتحقق من توحيد `POS_API_TOKEN` بين عمليات الخادم وضبط ساعته؛ لا تُعطّل التحقق من الجلسات أو كلمة مرور اعتماد الجرد.

إذا ظهر خطأ ODBC «استخدام غير صحيح للقيمة الخالية (Null)» عند حفظ المسودة، فحدّث الخادم وأعد تشغيله: تُقرأ تواريخ الاعتماد الفارغة دون تحويل `CDbl(NULL)`، وتبقى فارغة حتى اعتماد الجرد. لا يحتاج هذا الإصلاح إلى تغيير الأرصدة أو حذف جداول الجرد.

يعرض الجرد قيمة النقص وقيمة الزيادة والصافي (الزيادة ناقص النقص) بسعر الشراء/التكلفة، مع فواصل الآلاف. تُحتسب الأصناف المعدودة فقط؛ لا تُعتبر الخانة الفارغة صفرًا. تُثبّت تكلفة كل صنف عند حفظه لأول مرة في الجرد لتبقى القيم التاريخية ثابتة عند تغيير أسعار البطاقة لاحقًا. يُضاف عمود التكلفة تلقائيًا عند تحديث الخادم؛ احفظ المسودات القديمة لتثبيت تكلفتها الحالية قبل اعتمادها. الجرد المعتمد القديم الذي لم يحفظ التكلفة يُظهر تنبيهًا بأن قيمة الفروق غير متاحة، دون اختلاق تكلفة تاريخية.

يمكن للمدير وأمين المخزن حذف المسودة بعد التأكيد دون تغيير المخزون، ولا يمكن حذف الجرد المعتمد. تُخفى المسودة المحذوفة من القائمة وتبقى محفوظة داخليًا بحالة حذف حتى لا يُعاد استخدام رقمها. لا يمكن للصنف الوجود في أكثر من مسودة مفتوحة؛ يظهر رقم المسودة التي تحجزه وتُعطّل إضافته، ويتحقق الخادم من ذلك داخل معاملة الحفظ والاعتماد أيضًا. يصبح الصنف متاحًا لجرد جديد بعد إزالته من مسودته وحفظها، أو حذف المسودة أو اعتمادها. عند وجود تكرار في مسودات قديمة، يجب إزالته من إحداها أو حذف المسودة المكررة قبل الاعتماد.

يمكن للمدير وأمين المخزن إضافة ملاحظات الجرد أو تعديلها بعد الحفظ وحتى بعد الاعتماد. في الجرد المعتمد يظهر زر «حفظ الملاحظات»؛ يحدّث الملاحظات فقط مع التحقق من نسخة المستند، دون تغيير الكميات أو التكلفة أو حالة الاعتماد أو اسم المُعتمد وتاريخه. لا تُفتح كميات الجرد المعتمد للتعديل. يفتح زر «طباعة الجرد» معاينة A4 للمسودة المحفوظة أو الجرد المعتمد، تشمل الرقم والحالة والأصناف وأرصدة الدفتر والعدّ وفروق الكميات والتكلفة وقيم النقص والزيادة والصافي والملاحظات وبيانات الإعداد والاعتماد. احفظ التعديلات والملاحظات قبل الطباعة؛ تظهر الكميات غير المعدودة بوضوح ولا تُعامل كصفر.

بعد حفظ صنف جديد يظل نموذج الإضافة مفتوحًا وتبقى جميع الحقول كما هي؛ يمكن تغيير اللون أو المواصفات ثم الحفظ لإضافة صنف مستقل، دون التحول إلى تعديل الصنف السابق. يستمر منع تكرار الصنف بنفس المواصفات. يُعطّل زر الحفظ أثناء الطلب، وتظهر رسائل النجاح والأخطاء داخل النموذج دون نافذة تأكيد أصلية تعطل التركيز في Electron. تُحدّث قائمة الأصناف في الخلفية دون شاشة تحميل. تعديل صنف موجود يحتفظ بسلوك إغلاق النموذج بعد نجاح التعديل.

```powershell
pnpm electron-dev
```

يشغّل الأمر خادم التطوير تلقائيًا على المنفذ 3005 (قابل للتغيير عبر `POS_DEV_PORT`)، وينتظر جاهزيته ثم يفتح Electron عليه، ويوجّه نداءات البيانات في وضع التطوير إلى خادم التطوير نفسه بدل عنوان `server.json` (يمكن تجاوز ذلك بضبط `POS_SERVER_URL`). لم يعد التطوير يستخدم المنفذ 3000 حتى لا يتعارض مع خادم الاستضافة الإنتاجي (`pnpm start:host`) الذي يعمل على 3000 في جهاز الخادم؛ التعارض السابق كان يجعل Electron يعرض بناء الإنتاج القديم بدل نسخة التطوير. إذا كان المنفذ 3005 مشغولًا يتوقف الأمر برسالة واضحة بدل تشغيل نسخة خاطئة.

يلزم أن يكون `ACCESS_DB_PATH` و`POS_API_TOKEN` مضبوطين على الخادم المحلي، وأن يتطابق الرمز مع ملف `server.json` الخاص ببيئة التطوير. لبناء تطبيق Electron:

إذا فشلت جميع عمليات التحميل برسالة `POS server returned an invalid response (404)`، فهذا يعني أن عنوان الخادم يعيد صفحة غير موجودة بدل واجهة البيانات، وليس أن الجداول فارغة. تحقق من `serverUrl` في `server.json`، ثم أوقف `pnpm dev` وأعد تشغيله إذا كان قد ظل مفتوحًا أثناء بناء نسخة Electron بالسكربت القديم. يستبعد بناء Electron الآن ملفات واجهات البيانات ووكيلها من التصدير بالإعدادات دون نقلها أو حذفها، ولا يحذف ذاكرة خادم التطوير؛ يحفظ Next.js ملفات سطح المكتب في `out` مع إبقاء ذاكرة التطوير في `.next\dev`. أبقِ صفحات سطح المكتب بصيغة `.tsx` وواجهات البيانات والوكيل بصيغة `.ts`.

```powershell
pnpm build:electron
pnpm package
```

الإصدار السادس هو `1.6.0`. ينتج بناء Windows ملف التثبيت `dist-v6\AlEntlaqPOS Setup 1.6.0.exe`، وتوجد النسخة غير المثبتة في `dist-v6\win-unpacked`. مجلد البناء مستقل عن مجلدات الإصدارات السابقة؛ لا يستبدل بيانات Access أو إعدادات اتصال المحطات. تحديث تطبيق المحطة لا يحدّث خدمة الخادم؛ انشر كود الخادم المحدّث وأعد تشغيل خدمته لتفعيل تعديلات واجهات البيانات.
